# Arrays and execution models

First identify what the public operation promises: values, labeled alignment, shape, dtype, metadata, laziness or execution cost. Use only the applicable dimensions in assertions; adding unspecified metadata requirements can reject valid repairs.

For xarray, inspect the checkout's `xarray.testing` helpers before choosing equality. Its documentation distinguishes approximate numeric comparison, equal values/coordinates, and stricter identity. For pandas, look for the corresponding local testing utilities and existing tests instead of reducing a labeled object to an unlabeled array. Confirm the installed helper's arguments; their defaults vary by version. [Xarray equality helpers](https://docs.xarray.dev/en/stable/generated/xarray.testing.assert_identical.html), [numeric comparison](https://docs.xarray.dev/en/stable/generated/xarray.testing.assert_allclose.html), [pandas contribution guide](https://pandas.pydata.org/docs/development/contributing.html).

For Dask or a sparse/lazy backend, check the local test's computation boundary. Graph construction success does not prove computed values, and converting everything eagerly may erase the behavior under test. Use a tiny deterministic input and compare the public result after the required computation. Inspect the chosen collection's local fixtures before introducing a scheduler or optional backend. Dask's main and distributed schedulers live in different repositories; availability of one does not establish the other. [Dask development guide](https://docs.dask.org/en/stable/develop.html).

For estimator behavior, distinguish constructor parameters, fitted state and returned predictions using a nearby estimator test. Validate reproducibility with the project's supported random-state mechanism when randomness affects the assertion. Avoid assuming a transformed value or fitted attribute must exist before fitting. [Scikit-learn estimator development](https://scikit-learn.org/stable/developers/develop.html).

For statistics, tensor contraction and query-backed data, inspect local examples for axis conventions, missing values and backend materialization only when implicated by the task. These are questions to resolve, not extra acceptance criteria. A numerical tolerance needs a scale/error justification; a self-written repair producing the same number is not one.
